## Workload and measurement

The offline harness drives the public `StratPerformer` using all seven actual
Reason factory patches and their MIDI scores from wrapper revision `7b0fa5be`:
Bridge Twang, Glassy Middle, In Between, Init, Neck Blues, Quack Rhythm, and
Slow Strum. Patch/MIDI hashes and the wrapper's control conversions are frozen
in `factory/provenance.json` and `factory/presets.tsv`. Lookahead, compressor,
pickup positions, note ownership, sustain, bend, and controller dispatch follow
that path. This is an offline model benchmark, not execution inside Reason.
The scores exercise repeated notes/chords, palm-wheel changes, pressure-driven
vibrato, legato/slide switches, and explicit stroke directions. Their event
counts are retained in `factory/midi-event-coverage.json`; pitch-wheel and pedal
handling are supported by the harness but are not present in these seven scores.

The native matrix is 48/96/192 kHz × 64/256 frames, all seven patches, three
rounds per build after one untimed warmup. Build order alternates A/B/C,
C/B/A, A/B/C, where A is original, B is acoustic pre-optimization, and C is
the optimized candidate. One shared-machine quiet slot serializes this work
against the other instrument owners.
The retained model runs at twice the host rate below 64 kHz, so these host
rates correspond to 96/96/192 kHz in the strings and circuit. Similar 48/96 kHz
CPU cost, followed by roughly twice the work at 192 kHz, follows that design.

Each callback records both `CLOCK_THREAD_CPUTIME_ID` and monotonic wall time
around event dispatch plus rendering. Preparation, hashing, statistics,
allocation of the pre-reserved timing vectors, and CSV/audio writes are outside
that bracket. Raw callback rows retain preset, rate, block size, repeat, callback
index, start frame, actual frame count, CPU nanoseconds, and wall nanoseconds.
The clocks separate elapsed time from calling-thread CPU consumption in the
same observation; thread CPU can include kernel/page-fault/accounting effects
and is not an instruction trace. Excess wall time also includes measurement
overhead, so it is not exclusively scheduler delay. Clock failure aborts the
benchmark. The analyzer requires complete, unique rows, unchanged frame counts,
finite output, and matching pre-optimization/optimized hashes in the actual
timing runs. It reports both ratios of median aggregate CPU and median paired
round ratios; callback percentiles use sorted index `floor(q*(N-1))`.
Per-run context also retains cgroup CPU accounting/quota, system CPU pressure,
and load snapshots. Observed factory maxima are not universal worst-case bounds.

The host is an AMD EPYC 9V74 virtual machine with five visible processors and
a four-core cgroup quota. Native DSP builds use GCC 14.2, C++17, `-O3 -DNDEBUG`
without fast-math. The separate portable build covers C++17 without exceptions,
RTTI, or builtins; parent validation additionally cross-compiles AArch64. These
are development-machine measurements, not a Reason SDK or hardware latency
guarantee.

## Profile-selected change

Callgrind 3.24 over all seven factory scores at 48 kHz/64 frames counted
61.067 billion instructions before optimization. Scalar left and right spatial
tap readers accounted for 9.29% and 8.48% of self instructions respectively.
Both polarizations use the same pickup location, weights, ring cursor, and
wrap boundaries. `readPickupPair` therefore shares their addressing and wrap
decision while retaining the four scalar dot products' association and the
final right-plus-left additions. It runs at the same state boundary, after
damping and before the rail cursor advances. Contact reads retain their scalar
helpers. No model state, interpolation weights, random sequence, or arithmetic
precision changes.

An identical Init-only profile with the final timing harness counts
9,286,274,781 instructions before and 8,582,904,494 after: a 7.57% reduction.
This is an instruction-count result, not a native timing claim.

A subsequent independent scan of all 4,558,293 measured callbacks also finds a

the other occurs between incoming MIDI events and may involve scheduled work.
At the pickup-optimization checkpoint, their median times are 346.5–424.4 µs
(median of position medians 390.5 µs), versus 363.1–456.6 µs (393.2 µs) in the
original. This repeated event cost is a real qualification limit for that small
buffer, not explained away by the isolated timing outliers.

## Repeated chord-event follow-up

Bounded Callgrind profiles render the exact prefix and collect only the selected
192 kHz/64-frame callback. At Quack Rhythm blocks 0 and 1,800, `designDispersion`
accounts for 84.88% and 81.42% of instructions respectively. Both invoke five
fits, with 2,573 calls each to `lossPhaseDelay` and `wrapResponse`. The loss/wrap
phases and target partial periods are invariant across all 42 coefficient trials.

Checkpoint `620a309` computes those invariant values once per fit in a 14-entry
stack array. It preserves the fundamental prefix, the separate partial loss and
wrap terms, `(base + loss) - wrap + dispersion`, the partial order/cutoff, and
all 40 golden-search iterations. There is no persistent cache, heap allocation,
approximation, or reduced fit accuracy. The original and candidate coefficients
are bit-identical in 6,984 independent cases: 5,544 raw-string configurations
(six constructions, six engine rates, 22 frets, seven tension ratios), plus
1,440 explicit solver cases covering upper/cutoff boundaries and zero included
partials. Those raw API rates include 22.05/24 kHz and do not imply that the
shipping wrapper exposes every test combination.

The two callback instruction counts fall from 3,722,251 to 1,765,217 (−52.58%)
and from 3,880,244 to 1,923,195 (−50.44%). The five fits remain, while loss/wrap
phase calls fall from 2,573 to 72 each. All 56 factory renders, 58,668,170 mono
frames, also remain byte-identical to acoustic checkpoint `0363599`.
These instruction counts are separate from the native follow-up below.

## Exactness

The direct oracle compares the new paired reader with the retained scalar
readers at every one of 8,192 ring cursors, four tap bases, and four fractions:
131,072 cases. Distinct finite random rail values cover both polarizations,
contiguous reads, and both wrap boundaries. Every output float is bit-identical.

Whole-score comparisons cover seven factory patches × 44.1/48/96/192 kHz ×
64/256-frame blocks: 56 cases and 58,668,170 mono frames (the same number of
float samples). The Strat guitar jack here is one channel, before any stereo
host routing. SHA-256 over the raw
float stream is identical before and after optimization in every case, and
each patch/rate is also identical across the two block sizes. The measured
factory samples therefore preserve the acoustic checkpoint exactly; this is
not a claim that a finite test exhausts every possible input.

## Afternoon follow-up: paired loop reads (2.4.3)

A Callgrind profile of `RenderStrat` over the seven Rack demo phrases put the
string loop's two fret-end reads and the pick and contact injections at the
top. While a string's tension stretch settles, both planes' read points move
every sample, so each recomputed its seventh-order Lagrange weights alone;
`StratString::loopTapPair` now computes both lanes together with the same
per-lane float arithmetic, and `inject` takes a contiguous path when its four
slots do not wrap the rail. A string also asks whether it is still driven only
after its coils read quiet.

Wall time for the seven phrases (66.3 s of audio at 48 kHz, `--tail 1`, the
renderers alternated three times on an otherwise idle development machine)
fell from 5.0–5.2 s to 4.2–4.3 s, about 18 %. Callgrind counts slightly more
instructions (6.92 to 7.12 G): the gain is the two weight chains running
side by side, which an instruction count does not show. Every phrase's WAV is
byte-identical before and after. These are development-machine figures, not
Reason CPU.

The pickup height of 2.4.3 adds one array index per coil and sample and a few
operations per fret or bend change; alternated wall time over the same seven
phrases stays within the run-to-run spread.
